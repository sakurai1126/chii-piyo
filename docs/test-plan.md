# テスト設計書

## 概要

本アプリケーションのテスト戦略・方針を定義する。
テストレベル、テスト環境、テスト観点、品質指標、テストデータ管理、モック戦略、自動化方針を記載し、個別のテストケースはテストケース表に記載する。

## テスト方針
### 基本方針

網羅そのものを目的とせず、ロジックが多く変更時に壊れやすい箇所を集中的に対応し品質を担保する。
具体的にはOpenAPI GeneratorやMybatis Generatorなどの自動生成コード、ConverterやRepositoryレイヤー、Server Actionsの呼び出しAPI等、それらとのやりとりのみの薄いロジックについては対象外としServiceレイヤー等のテストを充実させる。
また、フロントもUIのスタイル的部分は省略しカスタムフック等のロジックを集中して対応する。

## テストレベル定義

### 単体テスト

| 項目 | 内容 |
| ------- | ---------------------------------------------------------- |
| スコープ | 個別の関数やコンポーネント |
| 使用ツール | バックエンド：JUnit + Mockito<br>フロントエンド：Vitest + Testing Library |
| 実行タイミング | PR時のCIパイプライン |
| 目的 | ビジネスロジックの正常系、境界値・異常系の検証 |

#### バックエンド単体テストの対象

| 対象 | テスト内容 |
| -------------------------------- | ------------------------------ |
| Service | ビジネスロジック、バリデーション、例外処理 |
| Controller | 各データ整形、判定処理、ステータスコード関連 |
| Security | JWT 検証、Audience 検証、認証ユーザー解決の分岐 |
| Scheduler | ゴミ箱クリーンアップ、サムネイル再生成の定期実行処理 |
| Common/Componentなど<br>横断的コンポーネント | ユーザー情報同期、S3キー生成、共通例外等 |

#### フロントエンド単体テストの対象

| 対象 | テスト内容 |
| -------------------- | ------------------------------- |
| ユーティリティ関数 | バリデーション、パラメータ生成、日付整形、グラフデータ生成など |
| カスタムフック | コンポーネントから切り出した多量の状態管理ロジック等 |

コンポーネントの見た目・スタイル・外部依存呼び出しの薄いラッパー等は対象外とする。

### 結合テスト

| 項目 | 内容 |
| ------- | ---------------------------- |
| スコープ | 複数レイヤーの連携、DB 連携 |
| 使用ツール | JUnit + Spring Boot Test |
| 実行タイミング | PR時のCIパイプライン |
| 目的 | API 全体フロー、DB 操作の整合性、認証・認可の検証 |

結合テストの対象

| 対象 | テスト内容 |
| -------- | -------------------- |
| API | リクエストからレスポンスまでの一連の処理 |
| 認証認可 | JWT 検証フィルター、権限チェック |
| トランザクション | ロールバック、データ整合性 |

※フロントエンドにおけるコンポーネント間連携等の結合テストは維持コストの観点からスコープ外とする。
フロントエンドは状態管理や関数の単体テストを厚くし、画面遷移や主要シナリオの担保はE2Eテストに寄せる方針とする。

### E2E テスト

| 項目 | 内容 |
| ------- | ---------------------- |
| スコープ | ユーザー操作の主要シナリオ |
| 使用ツール | Playwright |
| 実行タイミング | PR時のCIパイプライン |
| 目的 | ユーザー視点での主要フローの動作確認 |

E2Eの選定基準はアップロードなどの機能をまたぐ長い導線、認証・認可やリダイレクトなどブラウザ遷移でしか確認できないものなど。
単純なCRUDなどは単体～結合テストで吸収する。

## テスト対象範囲

### 対象

| 対象 | 選定理由 |
| -------------------------------- | -------------------------------------------------------------------- |
| サービス層のビジネスロジック | 本アプリケーションのロジックが集中しているため |
| 権限判定・共有範囲・ゴミ箱の保持期間 | バグがUXに直結するため異常系・境界のテスト価値が高いため |
| セキュリティ・認証ロジック | 壊れると全APIに影響するため |
| 共通例外処理 | エラー発生時の特定作業に関連するためおさえておきたいため |
| 定期実行処理 | 30日経過データの完全削除を含むことからバグが起きた時のリスクが高いため |
| コントローラー層 | サービス層から受け取った結果をコンバーターに通すため整形などを行いロジックを持っている箇所が多々あるため |
| フロントエンド<br>単純な関数・バリデーション | 入出力が明確でテスト効果がわかりやすい |
| フロントエンド<br>認証・フック | フロントエンド側のロジックの集中箇所であるため |
| アップロード導線 | 多層が絡み合う複雑な箇所だがメディア管理アプリケーションの中核になる機能でありE2Eの優先対象となるため |

### 非対象

| 対象外 | 除外理由 |
| ------------- | --------------------------------------------- |
| UIの見た目・スタイル | 自動テストに不向きで維持コストに見合わないため |
| 自動生成コード | 生成物であり手動テスト対象外のため |
| データを受け渡すだけの処理 | リポジトリ層などは基本的にMyBatisマッパーへの受け渡しのみであり独自ロジックがないため |

## テスト観点

### 権限モデル

権限は2ロールで構成される。
権限を伴う操作は両ロールでの挙動を検証する。

| ロール | 想定ユーザー | 操作範囲 |
| --- | ---------- | -------------------------------- |
| 管理者 | 自分・妻 | 全機能の操作が可能 |
| 閲覧者 | 祖父母・兄弟姉妹など | 閲覧、アップロード、一部育児記録の閲覧、コメント・いいねのみ可能 |

### 対象とするエラーコード

異常系テストでは共通例外処理が下記を正しく返すことを検証する。

| エラーコード | 検証する状況 |
| ----------------------- | ---------------- |
| `VALIDATION_ERROR` | 入力値が不正なとき |
| `UNAUTHORIZED` | 未認証でアクセスしたとき |
| `FORBIDDEN` | 権限のない操作を行ったとき |
| `NOT_FOUND` | 存在しないリソースを指定したとき |
| `INTERNAL_SERVER_ERROR` | 想定外のサーバーエラー時 |

## 目標品質指標

数値は達成自体を目的とせず、重要ロジックの異常系・境界が押さえられていることを重視する。

| 指標 | 目標値 | 計測方法 |
| --------------- | ------------------------------- | --------------- |
| カバレッジ - バックエンド | 80% 以上 | JaCoCo |
| カバレッジ - フロントエンド | 70% 以上 | Vitest coverage |
| 結合テスト | 認証・認可・例外ハンドラ・主要CRUD・トランザクションを網羅 | ケース網羅 |
| 共通例外処理 | 全エラーコードの分岐を検証 | ケース網羅 |
| E2E | 主要導線がすべて成功 | 実行結果 |

### カバレッジ計測方針

- **計測対象:** テスト対象として定義したサービス層、セキュリティクラス、ユーティリティ関数、カスタムフック
- **ツール設定による除外:** 自動生成コードや設定クラス、UIコンポーネント等は、JaCoCo およびVitestの設定ファイルで明示的に計測対象から除外する
※特にフロントエンドはスタイル関連やマッパー的な実装も多いため、単純なロジック部分に限定しテスト価値の低い箇所はディレクトリ・ファイル単位でパターン指定して除外する方針とする

## 外部サービスのモック方針

**AWS Cognito**
単体・結合テスト: トークン検証ロジック等をモック化し、AWSへの実際の通信を発生させずにテスト
E2E テスト: テスト専用のアカウントを用いて実際の認証フローを検証

**AWS S3**
全テスト共通: 実際にS3へ通信は行わず、Presigned URL発行処理やアップロードロジックをモック化して検証。

## CI での実行方針

- テスト失敗時はマージをブロックする。
- カバレッジレポートを成果物として出力する。
